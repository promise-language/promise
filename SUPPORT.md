# Support

Promise is early and not production-ready. Support is best-effort from one
maintainer (George Djabarov). Filing the right thing in the right place is the
fastest way to get a useful response.

**Bug, crash, or wrong compiler behavior** — open an
[Issue](https://github.com/promise-language/promise/issues/new/choose). Include the
output of `promise version`, your OS and architecture (e.g. macOS arm64, Linux
x86_64, Windows x64, or the WASM target), and the smallest `.pr` file that
reproduces it along with the exact command you ran. A small repro gets looked at;
"it crashes sometimes" does not.

**"How do I…" or "why does the language work this way"** — ask in
[Discussions → Q&A](https://github.com/promise-language/promise/discussions/categories/q-a).
It's searchable, so an answer helps the next person with the same question.

**Language or standard-library proposal** — start in
[Discussions → Ideas](https://github.com/promise-language/promise/discussions/categories/ideas).
Once the design is settled it moves to a feature-request Issue to track the work,
then a PR. Don't open a PR first.

**Security vulnerability** — do not open a public Issue, PR, or Discussion. Report
it privately per [SECURITY.md](SECURITY.md).

**Anything else** — email hello@promise-lang.org.
